The log

The log

Findings, work and decisions, with their evidence. Newest first.

L0202026-10-18work

Template 0.5 exports saved fitted curves and diagnostics

Extended the existing Matplotlib adapter to consume an exact saved SciPy result without refitting. The optional combined app offers data-only or fitted output, with a residual panel and approximate parameter errors, plus full covariance, solver versions and input/result hashes in a JSON report. Missing, stale, malformed and unfinished fits are refused; failure and cancellation preserve the existing output protection. Renderer, host, visible-picker and omission checks define admission. GUM, Monte Carlo and coverage intervals remain separate numerical qualification work.

Evidence: apps/fitted-publication-workbench.json; audit/fitted-publication-qualification.json

L0192026-10-18work

Template 0.4 connects optional SciPy fitting to the linked editor

Adopted SciPy for straight-line and saturating-exponential fits with explicit unweighted or absolute independent y-sigma weighting. NIST Norris and Misra1a reference checks, including both nonlinear starts, and an independent weighted-line calculation validate the bounded numerical contract. The generated editor refits after cell edits, point moves, insertion and removal; completed results retain input-node and data/specification hashes, covariance, residuals and solver versions. Saved results restore across branches and reopen. Failure, cancellation, obsolete-job, omission and actual-host checks define admission. A visible test initially used the base interpreter after resolving a virtual-environment symlink; preserving the environment path corrected the test setup. GUM, Monte Carlo, x errors and fitted-figure exports remain separate work. The construction skill, reference guide and project site now describe the optional offer.

Evidence: apps/fitting-workbench.json; template/packages/fitting-scipy/; audit/fitting-adapter-qualification.json

L0182026-10-18work

Template 0.3 adds optional publication figures with saved-state provenance

Adapted the existing Matplotlib renderer as an optional package requiring linked-data. The command saves and captures the exact project, creates a new figure bundle with input-node and source/output hashes, supports cancellation, and records outcomes in the project journal. Mathtext PDF/SVG/PNG and LaTeX PDF are distinct choices. Python and TeX remain external dependencies; isolated execution exposed a missing package environment, resolved with a dedicated pinned environment. Constructor omission, renderer, dependency failure, host and visual checks define the admitted scope. Native save-dialog completion, physical printing and forced-crash export recovery remain outside qualification.

Evidence: apps/publication-workbench.json; template/packages/publication-matplotlib/; audit/publication-adapter-qualification.json

L0172026-10-17finding

Separate saved checkpoints from automatic crash recovery

The pinned Code - OSS source skips persistent window-backup registration in extension-development mode. Normal generated launches now install into the app's isolated extension directory; API tests retain development mode. Installed-mode forced-crash trials produced backup files but the tested reopen flow loaded the saved document instead of the unsaved edit. Automatic unsaved crash recovery is therefore excluded from admission. Explicit save/checkpoint restoration and interrupted atomic-save behavior have separate passing tests. The failure remains recorded for further investigation.

Evidence: audit/linked-editor-crash-check.json; template/assets/scripts/run.py; brief R21

L0162026-10-17work

Template 0.2 composes the optional linked-data editor

Added schema 2 package selection while retaining schema 1 and the neutral default. The linked-data package reuses pinned Tabulator, Plotly and Trrack in a custom editor with shared data, revision-checked mean calculations, persistent data undo/redo, named checkpoints and branches. A portable checksummed document retains data, results, actions and errors. Tests cover deterministic composition, omission, saved-state restoration, failed edits, overlapping and stale calculations, external-file conflicts, interrupted atomic saves and a Git fresh-clone round trip. Host and visible interaction evidence define the admitted scope.

Evidence: apps/linked-workbench.json; template/packages/linked-data/; audit/linked-editor-qualification.json

Reuse Git and qualify GitHub as a separate project connection

Recorded the user request for Git and GitHub availability. Inspected the pinned git-base, git, github and github-authentication manifests and reviewed official GitHub and Git LFS guidance. A disposable Git CLI experiment passed checkpoint commits, branching, local-remote transfer, fresh-clone restoration and artifact hash verification. This does not qualify the branded fork's Git UI, GitHub authentication or LFS upload. Proposed portable journal checkpoints and explicit artifact policies under R21.

L0112026-10-17decision

Appearance and visual tools are optional constructor offers

The user requested a TRAE-inspired appearance and central tables, plots, figures and interactive views, then explicitly clarified that visual tools must be offers selected for each application rather than mandatory features of the foundation. Recorded requirements R12-R14 and ideas I09-I10, and updated the roadmap and construction skill. The proposed implementation separates appearance, data core and editor adapter; linked views share one document and reject stale asynchronous results. Reviewed official custom-editor, webview, theme and TRAE settings documentation. These are requirements and design proposals, not newly implemented recipes; template 0.1 and both generated examples are unchanged.

L0102026-10-17work

Template 0.1 generates projects and prepares isolated fork source

Implemented deterministic generation, distinct product identities, two reversible layout recipes, a neutral document workflow, core and host tests, and separate Code - OSS source preparation. The construction skill is discoverable in the project and reads the actual registry and generator. Unsupported hiding, disabling and exclusion fail explicitly. Host tests exercise document editing, undo and redo, saving and reopening, diagnostics, tree contents and layout restoration. macOS testing exposed an IPC path-length limit, addressed with short isolated state paths. Visual testing also caught an older VSCodium activity-bar schema mismatch that settings assertions missed; template 0.1 therefore requires host API 1.112.0 or newer. The prepared source retains the pinned baseline and unresolved LFS pointers; it has not been compiled or packaged.

Evidence: tools/compose_app.py; template/; tests/test_composer.py; audit/template-verification.json

This choice starts an experiment; it does not certify general modular removal or select a domain for future apps.
