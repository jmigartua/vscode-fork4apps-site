The macroscopic workbench map

The macroscopic workbench map

Select a region to understand its job and the code behind it. Toggle visibility to explore a focused interface. The rest of the catalogue covers capabilities that sit beneath or across these regions.

The familiar layout is a default arrangement, not a fixed architecture: views and panels can move. The right sidebar can host a domain inspector, but the scientific inspector itself must be implemented. An installed extension appears in the Activity Bar only when it contributes an appropriate view container. Tree View and container API.

Conceptual layout preview only. These controls do not configure VS Code, stop background services or remove code.

Editor groups

The central document area holds text and custom editors. Select a region for details.

How to change a capability

Start with supported layout actions and contribution APIs. Use a domain extension for trees, commands and custom document views. Change the source only for product behaviour the extension surface cannot express, and keep each such change in the patch register. Visibility changes are the first level of customization; physical exclusion is a different engineering task.

The capability catalogue

Each entry names a role, usual placement and source area. The listed prerequisites are selected design constraints, not a complete dependency graph. “Source-location-verified” means the file or directory exists at the pinned revision; it does not mean its removal is safe.
